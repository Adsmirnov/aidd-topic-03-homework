## Что делал агент и какие были проблемы

**Задания 1–2.** Прочитал около 50 файлов и создал `ANALYSIS.md` со ссылками на строки кода. Получилось 10 функциональных требований и 9 пунктов «неоднозначности и дефекты», вмешательств почти не понадобилось.

**Задание 3, часть 1 (самая долгая, 25 вмешательств):**
1. Обнаружил, что `tinkoff-investments` нет на PyPI. Изучил архивный официальный репозиторий `Tinkoff/invest-python`: его `pyproject.toml` и `setup.cfg`, тег `0.2.0-beta59`. Пробно установил его по коммиту `1cc8495` (`pip install --dry-run`).
2. Понял, что SDK тянет зависимость `tinkoff`, которой тоже нет на PyPI. Сделал вывод: «сохраняю функциональность через официальный REST endpoint с `requests`, вместо закрепления неустанавливаемого VCS-пакета». **gRPC SDK заменён на прямые HTTP-запросы** (`dashboard/services/tinkoff_api.py`).
3. Собственная ошибка: в `requirements.txt` осталась строка `grpcio==1.51.3`, и установка зависла на сборке. Агент нашёл её, остановил процесс и удалил строку.
4. PowerShell отклонил одну команду с оператором `&`; агент повторил её в другой форме.
5. Порт 5432 был занят, поэтому Postgres вынесен на 5433, а Redis на 6380.
6. `README.md` агент переписал целиком: исходные инструкции заменены новыми. Пользователь этого не ожидал.
7. Пользователь опасался, что агент изменит сертификаты Windows. Агент таких команд не предлагал; все команды пользователь проверял перед подтверждением, некоторые сверял с Claude.

**Задание 3, часть 2.** Вынес разбор времени в общий модуль. Сам нашёл несовместимость с Plotly 7 (упал сквозной тест) и исправил её отдельным коммитом. Запустил `runserver`, worker (`-P solo`) и beat, проверил страницы HTTP-запросами. Тестов стало 25. В `ANALYSIS.md` добавил таблицу проверки требований и честно отметил, что импорт и котировки без токена не проверялись.

**Задание 4.** Сначала записал требования и архитектуру, затем сделал по одному коммиту на функцию. Сам заметил, что `login_required` ведёт на несуществующий `/accounts/login/`, и привязал защиту к `user:auth`. Сам составлял себе список дел и выполнял его по пунктам.

**Сбои сервиса Copilot (задание 4):**
* 23:01: `Sorry, your request failed… Reason: token expired or invalid: 403` — работа прервалась на середине;
* сразу после этого `Reason: key is missing`;
* после повторных «Try Again» работа продолжилась с 23:07.

**Корректировки от пользователя:** по сути решений не было. Вмешательства — это подтверждения команд, два «Continue to iterate?» и два «Try Again».

## Как проверялись результаты

* **Самим агентом:** 42 автотеста; `manage.py check`, `pip check`, `docker compose config`; HTTP-проверки запущенного сервера.
* **Независимо, Claude Code после завершения работы.** Те же тесты прошли (42 OK). Временные проверки тех же дефектов на ветке `copilot` — подробности в `COMPARISON.md`:
  * найдено, что карточка акции без токена падает с 500 (`RuntimeError: TINKOFF_TOKEN is not configured`);
  * пароль из одного символа принимается;
  * поиск по регулярному выражению заменён поиском по подстроке, то есть поведение API изменено.

## Итерация с настоящим API (2026-10-25, по требованию преподавателя)

* **Промпт:** проверить приложение с настоящим токеном (только чтение): `add_shares`, обновление цен, карточка с графиком, срабатывание уровня и стратегии на реальной цене; исправить ошибки, добавить тесты, описать в `ANALYSIS.md`. Ограничения: не выводить токен, не трогать сертификаты Windows, не отключать TLS, не ставить пакеты из неофициальных источников.
* **Ход работы:**
  1. `add_shares` → `CERTIFICATE_VERIFY_FAILED` (self-signed в цепочке). Агент **остановился и спросил решение**, ничего не обходя. Диагноз при этом был неточным: агент предположил «TLS-перехват в сети», хотя сертификат API выпущен Минцифры.
  2. **Корректировка от пользователя:** «это не перехват, сертификат выпущен Минцифры; разрешаю доверять этому корню только внутри приложения, не в Windows и не в общем certifi; возьми его из официального источника и проверь».
  3. Агент скачал сертификат по двум официальным адресам `gu-st.ru` и сравнил SHA-256 **файлов** (`936A43FE…`): они совпали. Сверку с цепочкой сервера API он не делал. Отпечаток **сертификата** (`D2:6D:…:CF:31`) позже проверил Claude Code: он совпадает с корнем сервера API.
  4. Пробный запрос с `REQUESTS_CA_BUNDLE` **прошёл проверку TLS**, но вернул **HTTP 404**: REST-адрес собирался неверно (`…contract.v1/MarketDataService/…` вместо `…contract.v1.MarketDataService/…`). Это ошибка агента из задания 3, тесты с моками её не ловили.
  5. Агент исправил сборку адреса в `dashboard/services/tinkoff_api.py`, но проверить не успел: интегрированный терминал VS Code перестал возвращать вывод команд. Новый терминал не помог: «обнаружение последней команды недоступно».
  6. Закончились бесплатные кредиты: 21 → 1,5.
* **Итог:** реальные данные в ветке `copilot` **не получены**. Правка адреса закоммичена с пометкой «не проверено». Настройка CA bundle в код не попала: агент передавал его только разово, переменной окружения в команде.
