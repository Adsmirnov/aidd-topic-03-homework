## Задание 3. Модернизация, дефекты, рефакторинг

* **Начало:** 20:19. **Конец:** 20:29 (≈ 10 мин работы агента, без ожидания пользователя), 5 коммитов.
* **Промпт:** тот же бриф: «аудит зависимостей, обнови до актуальных совместимых версий, секреты в `.env`, исправь баги, рефакторинг, тесты, обязательно запусти приложение и проверь функциональность против требований; коммиты с исправлениями отдельно от рефакторинга».
* **Порядок работы:** (1) обновление зависимостей и конфигурации → исходные тесты на новых версиях; (2) сначала тесты, воспроизводящие дефекты (14 упали), потом исправления (все прошли); (3) рефакторинг под защитой тестов; (4) запуск всех процессов и ручная проверка через HTTP.
* **Проблемы и как агент их решил:**
  1. `pip install` → `No matching distribution found for tinkoff-investments` (удалён с PyPI). Реестр Т-Банка `opensource.tbank.ru` недоступен (обрыв соединения). Агент нашёл зеркало SDK на GitHub и установил его по тегу.
  2. Установка SDK → `No matching distribution found for tinkoff<0.2.0,>=0.1.1`. Агент проверил импорты SDK, выяснил, что пакет `tinkoff` не используется (SDK сам содержит `tinkoff/__init__.py`), и установил SDK с `--no-deps`, перечислив его реальные зависимости.
  3. `import tinkoff.invest` → `TypeError: Metaclasses with custom tp_new are not supported` (protobuf 4.x на Python 3.14). Агент попробовал protobuf 5.29 и 6.33: импорт работал на обоих, но поиск по коду SDK показал вызов `SymbolDatabase.GetPrototype`, которого в 6.x уже нет. Выбран 5.29.6.
  4. Порт 5432 занят локальным Postgres пользователя → порт контейнера вынесен в `POSTGRES_PORT` (в локальном `.env` указан 5434). Docker Desktop не был запущен — агент запустил его сам.
  5. После обновления тест упал: `plot() got an unexpected keyword argument 'show_link'` (Plotly 7). На исходной версии этого дефекта не было, он появился при обновлении. Без теста график сломался бы незаметно.
  6. Исходные тесты API (6 шт.) ожидали, что гость может создавать и удалять акции, то есть закрепляли дефект Д-14. Агент не стал откатывать исправление, а добавил в тесты авторизацию и описал это решение.
  7. Запуск: T-Invest API отвечает `CERTIFICATE_VERIFY_FAILED: self signed certificate in certificate chain`. Агент проверил цепочку через `openssl s_client`: сертификат выпущен «Russian Trusted Root CA» Минцифры, которого нет в корневых сертификатах gRPC. Решение требует согласия пользователя: нужно скачать корневой сертификат и доверять ему в приложении.
* **Корректировки от пользователя:** нет.
* **Как проверялось:** 36 автотестов; `manage.py check`, `makemigrations --check`; HTTP-запросы ко всем страницам и API к запущенному серверу (таблица в разделе 17 `ANALYSIS.md`); логи beat/worker (задача ставится каждые 10 с и выполняется).
